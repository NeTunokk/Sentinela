Sentinela — como usar este pacote
=================================

Este pacote já traz os executáveis compilados e a imagem do PostgreSQL 16.
Você NÃO precisa instalar Rust, compilar nada, nem baixar imagens do Docker.

1. Requisito único: Docker em execução.

   Linux   -> Docker Engine (rootful), com seu usuário no grupo "docker".
   Windows -> Docker Desktop em execução.
   macOS   -> Docker Desktop em execução.

   A verificação de integridade roda dentro de um container descartável, por
   isso o Docker é obrigatório. É ele que garante o isolamento da restauração.

2. Abra o painel com duplo clique (ou pelo terminal):

   Windows:      sentinela-server.exe
   Linux/macOS:  ./sentinela-server

   O navegador abre sozinho em:  http://127.0.0.1:8787

   Se você abrir de novo, o programa apenas traz a página que já está no ar
   para a frente — ele não inicia um segundo servidor.

   Opcional: instale o painel como aplicativo (PWA). Com ele aberto no
   Chrome/Edge, clique em "Instalar aplicativo" no canto esquerdo do painel
   (ou use o menu do navegador). Depois disso, ao iniciar o servidor, ele abre
   o aplicativo instalado automaticamente; se o app ainda não estiver
   instalado, abre em uma janela de aplicativo do Chrome/Edge e, sem Chromium,
   no navegador padrão. O parâmetro "--browser" força o navegador e
   "--no-open" não abre nada. Instale o app na mesma porta do servidor
   (padrão 8787).

3. Em "Ambientes", crie um ambiente apontando para:

   - a pasta onde estão os arquivos .dump
   - a pasta onde estão os testes SQL (arquivos YAML)

4. Clique em "Testar" no backup que quiser verificar.
   O resultado aparece em "Execuções", com relatório assinado.

5. Para encerrar: use o botão "Encerrar servidor", no canto inferior esquerdo
   do painel. Ele mostra "Servidor encerrado", fecha a janela (quando o
   navegador permite) e derruba o servidor local.

A imagem do PostgreSQL
----------------------

O arquivo postgres16.tar.gz (ou postgres16.tar) fica na mesma pasta dos
executáveis. Na primeira execução o Sentinela o carrega automaticamente com
"docker load". Isso leva alguns segundos e ocupa cerca de 700 MB no disco do
Docker; nas execuções seguintes a imagem já está pronta e nada é recarregado.

O programa não acessa a rede: ele nunca faz "docker pull".

Se o arquivo não estiver na pasta, o painel mostra um erro explicando. Nesse
caso, carregue manualmente:

   docker load -i postgres16.tar.gz

Instalações compartilhadas (avançado):

   SENTINELA_IMAGE_DIR=/caminho/da/pasta    procura o arquivo nessa pasta
   SENTINELA_IMAGE_FILE=/caminho/arquivo    usa exatamente esse arquivo

Linha de comando (opcional):

   ./sentinela --help
   ./sentinela env add
   ./sentinela run --env NOME_DO_AMBIENTE

   ./sentinela-server --port 8790      outra porta
   ./sentinela-server --no-open        não abre o navegador

Conferir a integridade do download:

   Linux/macOS:
     sha256sum -c sentinela-<versao>-<sistema>-<arquitetura>.tar.gz.sha256

   Windows (PowerShell):
     Get-FileHash .\sentinela-<versao>-windows-x86_64.zip -Algorithm SHA256

Onde ficam os dados (criados na primeira execução):

   ~/.config/sentinela/        ambientes (YAML)
   ~/.local/share/sentinela/   histórico, relatórios assinados e chave Ed25519

No Windows, "~" é a sua pasta de usuário (C:\Users\<nome>).

Para desinstalar: apague os dois diretórios acima e os executáveis. A imagem
carregada no Docker pode ser removida com "docker rmi postgres:16".

Observação sobre Windows nativo: o painel, a lista de backups e o SHA-256
funcionam normalmente, mas a prova de restauração ainda depende de correções no
tratamento de caminhos com ":" (é o mesmo bloqueio de antes, não é causado por
este pacote). Em Linux e WSL2 o fluxo completo funciona.
